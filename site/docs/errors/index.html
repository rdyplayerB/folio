Finding codes

Every code folio validate can emit, what causes it, and what to do. Errors block certification. Warnings do not, and the T4 warnings in particular are opinions rather than faults.

Why this page exists

A validator that refuses your game without saying why is worse than no validator. Every code the engine can produce has an entry here, and the intent is that adding one without documenting it should be impossible.

T0 · schema

The manifest and the container. Nothing else runs until these pass.

E100
manifest is missing a mandatory field. All seven of id, title, author, folioVersion, logicType, license and contentRating are required. See the manifest reference.
E101
A manifest field is the wrong type. All seven are strings, including folioVersion.
E102
folioVersion is not semver. Three dot-separated numbers, so "0.1.0" rather than "0.1".
E103
Unknown logicType. Only world and zmachine exist.
E104
Unknown contentRating. One of all-ages, teen, mature.
E107
The walkthrough is empty. It is the proof of completability, so a game without one cannot certify. Even a one-line walkthrough is better than none.
W105
Licence is "unknown". Playable, but the gallery cannot serve a game whose rights are undeclared. Set an SPDX identifier once you know.
W106
No aiDisclosure block. State precisely what was generated and what a human reviewed. A claim that outruns the pipeline is the failure mode that costs trust.
W108
brief.json could not be read. The game is judged against generic defaults instead of your stated intent, which usually means harsher T4 warnings than you deserve.

T1 · integrity

Every reference resolves and every asset decodes.

E200
Declared zmachine but no story file. Needs a logic/*.z3, .z5 or .z8.
E201
That is not a Z-machine story. Its first byte is not 3, 5 or 8. Usually a wrapped or base64 file rather than the raw binary.
E202
Extension and header disagree. A file named .z3 whose header says v5. Rename it, or ship the story you meant to ship. This is checked because the mistake otherwise surfaces in front of a player.
E203
No presentation/roommap.json. Path A needs one to bind object numbers to stable ids. Generate it with folio calibrate, see Porting a game.
E204
roommap.json is not valid JSON.
E205
roommap.json is missing a key. ROOMMAP, OBJMAP, ATTR and ADVENTURER are all required. If you generated it, you probably still have flags left in the _confirm block.
E206
The room map's ATTR table is incomplete. The engine reads ten named ZIL flags and the message lists the ones you are missing. This is an error rather than a warning because the game will boot, play correctly in a terminal, and be silently wrong everywhere it is drawn: nothing reads as takeable, no container ever looks open, the lamp never looks lit. Run folio calibrate and read the census it prints, matching the bit whose sample object names fit the meaning.
E207
The room map still carries its _confirm block. Calibration leaves that behind listing what it could not work out. Fill those flags in and delete the block. A shipped game should not be carrying its own to-do list.
E210
Declared world but no logic/world.json.
E211
world.json is not valid JSON. The message carries the parser's position.
E212
world.json violates the schema. Checked against the published schema, and the message names the exact path, as in rooms[0].descriptoin is not a known field. Unknown fields are errors rather than warnings because at this size they are always typos, and a field nothing reads is indistinguishable from a feature that does not work. Shape is checked before meaning, so a game failing here has not had its graph analysed yet and may have further problems behind these.
E220
Unknown capability. The game is asking for an engine feature this format version does not define. Known values are listed in the manifest reference.
E230
A .png is not a PNG. Its magic bytes are wrong. Assets are checked here because a bad one otherwise fails at play time.

T2 · graph

The dependency graph, computed from the world rather than taken on trust. This is where dead ends are caught, and it runs on Path B only, because a compiled binary's graph cannot be read.

E300
meta.start is not a real room. Nothing can boot. Check spelling and case.
E301
An exit leads to a room that does not exist. The message names both ends.
E302
An exit's door is not an item. A door has to be a real item id, and it needs to exist even if the player never picks it up.
E303
An item starts nowhere real. location must be a room id, another item's id, "PLAYER" or "NOWHERE".
E304
A rule sends the player to a room that does not exist. A goto with a bad target.
E305
A rule acts on an item that does not exist. Usually a typo in an effect's item.
E310
The win state is not reachable. The one every first draft hits. Either nothing declares a win effect at all, or a puzzle in the chain has no solution from the start state. Work backwards from the win: what condition guards it, what sets that, and is that reachable in turn?
E311
A room is unreachable. Nothing the player can do leads there. Usually a missing return exit or a condition nothing satisfies.
W312
An item can never be reached. It exists but no player will ever see it. Often left in a room you later made unreachable.
W313
A rule can never fire. Its room is unreachable, or its noun can never be present. Reported from the trigger and never from the conditions, because a rule with conditions that fail is a deliberate failure branch and not dead code.
W314
An item can be destroyed but is also required. A player who destroys it first may be unable to finish. Make it unbreakable, replaceable, or make the destruction itself a win or lose branch.

T3 · replay

Your walkthrough is run from a cold start, with no state injected and no privileged verbs, and it has to reach the ending.

E400
The walkthrough contains no commands. Every line was a comment or blank.
E401
The game would not start. Usually a malformed meta block.
E402
Unknown assertion. Only expect: score N, expect: room ID and expect: moves N exist.
E403
An assertion failed. The line number counts commands, not file lines, so comments and blanks are not included in the count.
E404
A command threw. A genuine engine-level fault. Worth reporting as a bug alongside the world that triggered it.
E410
The walkthrough ended without winning. The hint reports where it stopped, the score, the move count and the last command, which is normally enough to see which step stopped working.
E411
The walkthrough ends in a loss. It reached a lose effect. The hint carries the death text.

T4 · design

Advisory, always. A shallow game is still a game; it simply cannot claim to be a finished one. Thresholds come from replaying Zork I and measuring what it does, and shipping a brief.json re-grades all of these against your own stated intent instead.

W500
Too few rooms. Short enough to read as a demo. If your source carries more named places than the adaptation used, the message says so, because that gap is the characteristic failure of compiling a long book into six rooms and a walk.
W501
The longest puzzle chain is shallow. Nothing requires several steps of planning. Depth is what makes a solution feel earned; a chain of one is an errand.
W502
Too few items do anything. Almost nothing is load-bearing. Zork carries a lot of scenery too, only 43% of what a player sees is ever picked up, but below about a quarter the world stops rewarding attention.
W503
Too few rooms contain anything. The rest are corridors, and empty rooms are the most common way a generated map inflates its size without adding a game.
W504
The map is a tree. Corridor maps are the signature of generated geography. Zork runs 0.67 loops per room, so nearly every room sits on a circuit, which is what lets a player take a shortcut and feel the map as a place rather than a menu. Measured per room, because one loop in a fifty-room map is still a corridor.
W505
Nothing can kill or defeat the player. Without stakes, exploration carries no tension. Not mandatory, and some fine games have no death, but worth having decided rather than defaulted. Setting deadliness: "none" in your brief silences it, because a dial must silence the warning it authorises.
W506
Keys sit in the same room as their locks. A key beside its door is a formality rather than a puzzle. Distance is what makes a player carry something in the hope that it matters.
W507
Almost everything is load-bearing. The opposite of W502. A world where everything matters reads as a shopping list, and Zork keeps roughly half its objects as pure scenery precisely so the useful ones feel chosen.
