Make one

Two ways in. Both end in a single file.

Whether you start with a story nobody has ever played or a game from 1984, you finish with a .folio — one file that anyone can open in a browser and that you can keep forever.

Bring a story

A novel, a screenplay, something you wrote.

Say what kind of game you want

Difficulty is not one quantity — it is how deep the puzzle chains run, how plainly clues are stated, how far a key sits from its lock, and how long the game dares to go without rewarding you. You set the intent; the compiler works out the numbers.

The compiler reads your source

It pulls out the places, the people, the objects that matter and the moments the story turns on — citing the passage each one came from, so you can check its work. If your source is a poor fit for an adventure, it says so up front rather than handing you a hollow game.

Structure first, prose second

The puzzles are built and checked as an abstract shape before a single sentence is written. That ordering is what stops a long book compiling into six rooms and a walk: bad structure is thrown away while it is still cheap.

It has to prove itself

The engine replays your walkthrough from a cold start — no teleporting, no conjured items — and has to reach the ending. It also checks that no dead ends exist, that your world is not mostly empty rooms, and that the shape resembles a game people actually finish. 

$ folio validate my-game.folio
PLAYABLE  my-game.folio  T0+T1+T2+T3+T4 passed
  completed in 214 moves for 180 points, 92% of rooms visited
  ran T0, T1, T2, T3, T4

Bring a game

Zork, an Inform project, anything from the IF Archive.

The original binary runs unmodified

Folio does not reimplement your game or paraphrase it. It runs the actual story file and reads the machine's live memory to work out what to draw. The game underneath is exactly the one people played; the pictures are a layer on top.

What you supply is the presentation: which room maps to which scene, and what the verb buttons send. That travels inside the .folio, so the engine stays generic and your game stays yours.

Start here

npm i -g folio-engine

folio pack my-game/ my-game.folio
folio validate my-game.folio
folio play my-game.folio

The command line does everything the site does. Documentation, the format specification, and the engine source all live on GitHub.
